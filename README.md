# 自我使用说明书 · 高考志愿探索版

> 先认识自己，再决定走向哪里。

自我使用说明书是一款面向高中生的 AI 专业探索网页。它从“什么事情会让你忘记时间”开始，通过连续情境对话、历史人物精神镜像和现实条件补充，帮助使用者看见自己的核心驱动、适合发挥的环境、容易耗电的状态，以及值得进一步了解的大学专业方向。

> 在线体验：[打开自我使用说明书](https://yusheng266186-beep.github.io/self-manual/) · 项目仓库：[查看源代码](https://github.com/yusheng266186-beep/self-manual)

## 项目定位

很多专业选择工具从分数、排名或职业名称开始，但学生真正困难的部分往往是：知道世界上有很多专业，却还说不清自己想过怎样的生活。

这个项目把专业选择拆回几个更接近个人经验的问题：

- 什么事情会让自己持续投入；
- 热爱变成长期任务后，是否仍愿意坚持；
- 更适合明确规则，还是更需要自主空间；
- 喜欢独自钻研，还是在人群协作中获得能量；
- 哪些人、环境和工作方式会快速消耗自己；
- 理想、能力、选科、成绩和现实限制应该怎样共同进入判断。

它不是院校录取预测工具，也不以一次对话给人贴上固定标签。最终说明书是一份可继续修改的探索稿，作用是帮助使用者提出更好的问题，再通过课程体验、招生资料和真实实践不断校准。

## 适合谁使用

- 面对大量大学专业，不知道从哪里开始了解的学生；
- 有兴趣方向，但担心“把热爱变成职业后会不会被消耗”的人；
- 不满足于简单性格测试，希望结合真实经历分析的人；
- 想同时看见专业吸引力、课程难度和就业环境的人；
- 希望在手机上完成一轮连续、沉浸式自我探索的人；
- 想在正式志愿调研前，先整理个人偏好和现实条件的人。

## 设计理念

### 不从专业名称开始

页面的第一段对话不是“你想学什么专业”，而是回到最近一次真正投入的经历。专业方向从热爱、边界、学习方式和生活期待中逐渐浮现。

### 不把人物当答案

历史人物卡片只承担“精神镜像”的作用。人物可以帮助使用者看见一种坚持方式或人生姿态，但不会直接决定专业推荐。

### 不回避现实

最终生成说明书前，页面会邀请使用者补充省份、选科、成绩或位次、城市、学费、体检和排斥方向等条件。信息不足时，报告会明确写“需核对”，而不是虚构录取判断。

### 不把结果写成定论

结果页使用“个人探索档案”的表达方式，强调方向不是结论。每个推荐专业都附带低成本验证方法，鼓励先体验课程和任务，再决定是否深入。

## 完整体验流程

### 1. 着迷

从做到忘记时间的事情开始，追问投入感来自创作、解决问题、研究生命、表达观点，还是与人协作。

### 2. 取舍

讨论爱好与职业之间的关系，例如：

- 热爱成为每天的任务后是否还能坚持；
- 更担心工作与兴趣无关，还是兴趣被工作消耗；
- 喜欢的事情应该成为专业，还是保留为生活中的自由空间。

### 3. 同路人

根据前面的回答匹配一位历史人物作为精神镜像。人物卡片包含：

- 标准人物资料和时代背景；
- 与当前回答相呼应的精神命题；
- 一段第一人称独白；
- 人物生平；
- 可进一步了解的现代专业方向；
- 真实学习与职业环境；
- 卡片内的短对话入口。

### 4. 发光

通过具体冲突场景理解使用者在什么环境下更容易发挥，例如：

- 标准答案明确的“温室”，还是高度自主的“荒野”；
- 独自把问题彻底研究清楚，还是与团队碰撞出想法；
- 稳定秩序、自由探索、持续表达和现实行动之间的偏好。

### 5. 说明书

继续识别耗电模式和边界，并在最终生成前补充现实条件。完成后生成一份结构化自我使用说明书。

## 核心功能

### 连续式 AI 对话

- 五段主题式进度：着迷、取舍、同路人、发光、说明书；
- 每轮提供不超过 4 个快捷选项；
- 支持直接输入自己的例外和复杂情况；
- AI 会结合前文继续追问，不把每轮回答割裂；
- 当前阶段同步显示在顶部；
- 等待期间显示明确状态，并暂时禁用重复发送。

### 历史人物共鸣卡

项目内置多位人物资料与对应主题，包括计算机、文学、医学、物理、法律、经济、数学、历史、生物、电气和翻译等方向。

卡片内容由本地标准资料和 AI 对话共同组成：

- 姓名、时代和生平采用本地人物数据库；
- AI 根据学生回答选择精神镜像；
- 人物短对话保持时代约束；
- “专业与现实”单独成页，避免浪漫叙事替代真实专业判断。

### 现实条件补充

说明书生成前可以填写：

- 所在省份；
- 当前选科组合；
- 成绩或位次区间；
- 排斥方向；
- 城市、学费、体检等限制。

也可以暂不填写。此时报告会将专业结果定义为继续调研方向，并提醒后续核对官方要求。

### 结构化个人说明书

最终报告包括：

- 专属称号；
- 一句话方向描述；
- 核心驱动；
- 发光条件；
- 使用须知；
- 已知 Bug 与耗电模式；
- 2—3 个可继续调研的专业方向。

前四个个人维度会按“一句话看见、具体理解、可以试试”的结构呈现，减少泛泛而谈。

### 专业方向卡片

每个专业方向包含：

- 为什么可能适合；
- 核心课程；
- 常见选科门槛；
- 真实学习困难；
- 常见就业环境；
- 未来七天可以完成的低成本验证方法。

专业方向只用于继续调研。最终选择应以本省考试院、院校招生章程、专业培养方案和个人实际条件为准。

### 保存、复制与恢复

- 保存完整说明书为高清图片；
- 一键复制说明书全文；
- 报告生成后继续补充个人情况；
- 进一步追问专业学习和就业环境；
- 重新开始一轮探索；
- localStorage 自动保存当前会话；
- 刷新或临时关闭页面后恢复上次进度。

## 视觉与交互设计

- 桌面端使用深色钛金属设备框架、动态岛和暖色玻璃界面；
- 手机宽度下自动铺满屏幕，不重复显示手机外壳；
- 以深灰、暖白、纸张色和低饱和红棕建立克制的编辑感；
- 首次进入使用主题卡片说明探索方式与预计时间；
- 对话气泡、选项、输入区和底部标签使用统一圆角和阴影层级；
- 结果页采用“个人探索档案”而非合格证或标准化测评视觉；
- 支持手机安全区和软键盘高度变化；
- 支持系统的减少动态效果偏好；
- 加载、发送、锁定、完成、保存和复制都有明确反馈。

## AI 对话与结果策略

### 对话约束

- 每轮只集中追问一个主题；
- 先回应使用者的具体内容，再进入下一段；
- 避免诊断、恐吓和夸张定性；
- 不用历史人物替代专业论证；
- 不根据单一兴趣直接下结论；
- 在现实条件不足时明确提示需要核对。

### 报告结构

模型按固定标记生成说明书，前端负责解析并渲染为独立报告卡片。即使模型偶尔遗漏部分格式，页面也会尝试识别正文并使用默认结构兜底。

### 请求稳定性

- 普通对话设置 45 秒等待窗口；
- 网络错误、限流和部分服务端错误自动重试；
- 长说明书使用更长等待窗口；
- 报告因输出长度中断时自动续写；
- 失败后恢复输入和快捷选项；
- 只有成功得到对应内容后才推进人物卡片或解锁报告，避免界面与对话错位。

## 技术实现

- 原生 HTML、CSS、JavaScript；
- 页面、样式、人物数据和交互集中在单个 index.html；
- 无 npm、无框架、无构建步骤；
- Fetch API 调用 DeepSeek Chat Completions 接口；
- 固定结构的提示词与报告解析器；
- localStorage 保存会话；
- visualViewport 处理手机软键盘；
- html2canvas 运行时加载并导出完整图片；
- Google Fonts 提供中英文排版，失败时回退系统字体；
- GitHub Pages 静态托管；
- 响应式布局和 prefers-reduced-motion 适配。

## 使用方式

### 在线使用

直接访问：

    https://yusheng266186-beep.github.io/self-manual/

页面打开后即可开始，不需要用户再次填写 API Key。AI 对话和说明书生成需要网络连接。

### 手机使用

1. 使用 Chrome、Edge、Safari 或其他现代浏览器打开页面；
2. 直接开始探索；
3. 如需更接近应用的体验，可通过浏览器菜单添加到主屏幕；
4. 页面在手机上会自动使用全屏布局。

### 本地预览

可以直接打开 index.html，也可以在仓库目录运行：

    python -m http.server 8080

然后访问：

    http://localhost:8080/

本地静态页面仍需要联网才能调用 AI 服务和加载部分外部资源。

## 部署与分支

当前仓库同时维护两个分支：

- main：默认代码分支；
- master：现有 GitHub Pages 发布分支。

更新页面或文档后，应保持两个分支的发布内容一致。

部署流程：

1. 修改 main 分支；
2. 提交并推送 main；
3. 将对应提交同步到 master；
4. 推送 master；
5. 等待 GitHub Pages 更新。

## 网络与本地数据

当前部署为打开即用的静态实验页面：

- 浏览器直接连接 DeepSeek 接口；
- 对话内容会发送到模型服务，用于生成回答；
- 当前谈心记录和最终说明书同时保存在本机浏览器；
- 页面没有账号、云端历史和跨设备同步；
- 清除站点数据、无痕模式或更换设备后，本地会话可能无法恢复；
- 保存图片和复制全文均在浏览器端完成。

如果将项目用于更大范围的公开访问，建议根据实际场景增加服务端请求中转、调用限额和独立的数据说明。

## 与「北辰」的区别

- **北辰**服务高一选科，重点是文理方向和 3+1+2 组合；
- **自我使用说明书**服务高考志愿前的专业探索，重点是驱动力、学习环境、专业课程和现实工作图景。

北辰更像一张选科方向星图；自我使用说明书更像一份进入专业世界之前的个人探索档案。

## 志愿调研清单

在根据说明书继续做实际选择时，至少还应核对：

1. 本省当年的招生计划和志愿规则；
2. 目标院校最新招生章程；
3. 专业选科、体检、单科成绩和外语要求；
4. 专业培养方案与核心课程；
5. 转专业、辅修、保研和实习政策；
6. 学费、城市、住宿和家庭条件；
7. 行业变化、真实岗位和就业去向；
8. 自己是否愿意亲自体验一门公开课或真实任务。

## 已知限制

- AI 输出具有随机性，相同回答可能得到不同表达；
- 页面不能预测录取结果；
- 专业名称、培养方案和选科要求会变化；
- 历史人物资料用于精神共鸣，不构成专业适配证明；
- 模型服务、网络或账户额度异常时，AI 功能可能暂时不可用；
- 外部字体或图片导出资源加载失败时会使用降级效果；
- 单次对话不能代替长期观察、真实课程体验和与老师家长的讨论。

## 维护清单

更新项目时，建议同步检查：

1. 五段探索是否自然推进；
2. 快捷选项和自由输入是否都能发送；
3. 人物卡片是否匹配正确人物资料；
4. 人物短对话是否保持时代与长度约束；
5. 现实条件面板是否能正确进入最终报告；
6. 2—3 个专业卡是否包含课程、门槛、困难、就业和七天验证；
7. 报告页是否可以保存完整图片和复制全文；
8. 刷新页面后会话是否恢复；
9. Android 和 iPhone 竖屏下是否没有横向溢出；
10. main 与 master 是否同步到同一版本。
